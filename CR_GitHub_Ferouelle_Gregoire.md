# 2. Git et GitHub

## Expliquez avec vos propres mots la différence entre Git et GitHub :

Git permet de gérer l'évolution d'un projet grâce à son historique tandis que GitHub permet notamment de stocker des dépôts Git à distance et de collaborer.


## Expliquez également le rôle de origin dans la commande "git remote add origin URL_DU_DEPOT":

Origin dans cette commande désigne le dépôt distant principal ou d'origine.  Son rôle est de simplifier l'utilisation de Git en permettant de faire référence à l'URL complète du serveur distant. 


# 3. Les principales commandes

## Indiquez le rôle des commandes suivantes :

- git init : Elle sert à initialiser un nouveau dépôt Git.
- git add : Elle sert à déplacer les fichiers modifiés ou nouveaux du répertoire de travail vers la zone de staging. 
- git commit : Elle sert à sauvegarder définitivement les modifications préparées dans la zone de staging.
- git push : Elle sert à téléverser les commits locaux d'une branche vers une branche correspondante sur un dépôt distant.
- git pull : Elle sert à récupérer et fusionner automatiquement les modifications d'un dépot distant dans la branche locale actuelle.
- git clone : Elle sert à copier une dépot existant vers un nouveau répertoire sur une machine locale.


# 4. Publication du projet

Il faut faire en sorte de synchronisez le dépôt local avec le serveur distant :

git push

# 6. Questions de compréhension

## Quelle est la différence entre git clone et git pull ? :

git clone est utilisé pour la première fois afin de créer une copie locale complète d'un dépôt distant alors que git pull sert à mettre à jour un dépôt local déjà existant avec les derniers changements provenant du dépôt distant. 


## Pourquoi est-il important d'avoir des messages de commit clairs ? : 

C'est important d'avoir des messages de commit clair surtout pour pouvoir se repérer dans le temps, puis cela aide à la traçabilités des différentes étapes précédentes.
